# Подключение Calendar Guard к обычному чату

Статус: серверная реализация; публичное размещение и подключение ещё не подтверждены.

Сервер — чистый обработчик: получает данные вызова, проверяет и возвращает результат. Не хранит события, не имеет Google OAuth-токенов, не читает чужие календари и не делает исходящих запросов. Поэтому для этой версии используется No authentication. Любой клиент может проверить собственный переданный JSON, но не получить состояние другого клиента. Для версии с хранением или прямой записью Calendar потребуются OAuth и отдельная серверная авторизация; эту версию нельзя использовать как такой шлюз.

## Локальная проверка

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest -v
.venv/bin/python server.py
```

В другом терминале: `.venv/bin/python test_mcp.py`.
Конечная точка: http://127.0.0.1:8000/mcp, состояние сервиса: /health.

## Размещение

Использовать Dockerfile или render.yaml в корне каталога. В пакет включаются только перечисленные исходники; не загружать live_*.json, резервные снимки, виртуальное окружение и личные события. Настройка Render external hostname читается автоматически. Для другого домена явно установить GUARD_ALLOWED_HOSTS. Нужен стабильный HTTPS-адрес, доступный ChatGPT. Бесплатный план — конфигурация для пилота, не обещание доступности тарифа или непрерывной работы; актуальные условия проверить перед размещением. Платный ресурс без отдельного согласия не создавать.

## Подключение ChatGPT

После фактического развёртывания и проверки /health и MCP initialize/tools/list:
1. Plugins → Add custom MCP server.
2. Ввести полученный реальный HTTPS URL с /mcp и имя Calendar Guard.
3. Authentication: No authentication (только эта stateless-версия).
4. Создать и установить плагин. Открыть обычный чат и выбрать Calendar Guard.
5. Попросить describe_format, затем проверить учебный пример из example.json через prepare_block. Не считать интеграцию подтверждённой до выполнения из обычного чата.

Для реального изменения чату нужны и Calendar Guard, и существующее подключение Calendar. Ассистент передаёт только необходимые поля. Не передавать пароли/токены. Вызов prepare_block не означает запись: отдельно выполнить check_current_event, разрешённое обновление Calendar и verify_update. Источник полей и защищённых интервалов — актуальный Planner. Сохранять returned plan в существующем durable state. Сервер не заменяет Meta-суждение и не блокирует обход через другой инструмент.

При недоступности сервера не менять управляемое событие напрямую. Сообщить конкретный блокер. До подтверждённой проверки обычного чата оставлять предыдущий Work-пилот на локальном проверенном маршруте.
